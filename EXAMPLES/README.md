# STM32 Examples

Bare-metal example projects for several STM32 microcontrollers, generated by
the [`stm32codegen`](https://github.com/a5021/stm32codegen) tool. Each example
blinks the board's on-board LED using only CMSIS (no HAL, no external
libraries) and is wired for three toolchains out of the box: GNU Make
(arm-none-eabi-gcc), Keil MDK-ARM, and SEGGER Embedded Studio (plus Ozone /
J-Link for flashing and debugging).

## How the generators work

Each `*.sh` script is a self-contained project generator. Running it:

1. Creates the directory tree (`inc/`, `src/`, `MDK-ARM/`).
2. Generates the CMSIS-based configuration headers with `stm32cgen`:
   - `inc/main.h` — top-level config (clock, SysTick, init order) and the
     `init()` sequence (`init_rcc` → `init_gpio` → `init_systick`).
   - `inc/rcc.h` — `init_rcc()` and the RCC clock-enable bits.
   - `inc/gpio.h` — `init_gpio()` and the GPIO macros. For the F1
     (`f103c8_demo`) this file is hand-written in the
     [BluePill_Project_Generator](https://github.com/a5021/BluePill_Project_Generator)
     style; for F0/F4/G0 it is emitted by `stm32cgen`.
3. Downloads the vendor CMSIS files (device header, startup, system init) and
   the SVD description from upstream sources (cached for re-runs).
4. Writes the application source `src/main.c`, the linker script, the Makefile,
   and the debugger/IDE configurations.
5. Builds the project with `make` to verify everything is consistent.

All downloaded files are cached — re-running the script skips what already
exists and only rebuilds.

### Prerequisites

- `bash` (native Linux/macOS, Cygwin, or WSL on Windows)
- `arm-none-eabi-gcc`, `make`, `curl`
- `stm32cgen` available via the `PY_GEN` environment variable (defaults to the
  repository root, i.e. one level above `EXAMPLES/`)

```sh
# from the EXAMPLES/ directory
bash ./f103c8_demo.sh
```

## How the demo works (f103c8 reference)

### Clock and SysTick

`main.h` sets `HCLK = 8` MHz (HSI, no PLL). `init_systick()` configures the
Cortex-M SysTick to fire every 1 ms:

```c
SysTick->LOAD = HCLK * 1000 / (8 - SYSTICK_CLOCK_SOURCE * 7) - 1;
```

With `SYSTICK_CLOCK_SOURCE = 0` the SysTick runs from `HCLK / 8` (1 MHz),
giving a 1 ms period. `SYSTICK_IRQ_ENABLE` selects between polling mode
(the default) and interrupt mode.

### GPIO — PC13 LED

The on-board LED is connected to **PC13** (active-low: writing the pin high
turns the LED off, low turns it on). `gpio.h` configures it with:

```c
#define PORT_C_CONFIG  PIN_CFG(13, O_2MHZ)   /* PC13: output, push-pull, 2 MHz */
#define PORT_C_STATE   PIN_HIGH(13)          /* PC13 HIGH = LED off            */
#define IOPC_EN        (PORT_C_CONFIG != 0)
```

`init_gpio()` first writes the idle state to `GPIOC->BSRR`, then writes the
full 64-bit `CRL+CRH` configuration through `*(uint64_t*)GPIOC_BASE`. Because
`IOPC_EN` is non-zero, `init_rcc()` enables `RCC->APB2ENR.IOPCEN`, which clocks
the GPIOC peripheral (on STM32F1 each GPIO port is gated by its own APB2 bit).

### Main loop

`src/main.c` runs the standard `for (init(); process(); idle());` loop. In
polling mode `idle()` calls `process_systick_event()`, which waits for the 1 ms
SysTick flag, increments a 64-bit uptime counter, and toggles PC13 based on
bit 9 of the counter — producing a visible blink with a period of
2^10 = 1024 ticks (~1 second).

In interrupt mode (`SYSTICK_IRQ_ENABLE = YES`) the same toggle logic runs inside
`SysTick_Handler()` and the `process_systick_event()` stub becomes empty.

## Flashing and debugging

Connect a J-Link (or ST-Link) to the board: SWDIO → PA13, SWCLK → PA14,
GND → GND, 3.3V → 3.3V (pinout varies by board — check the silk screen).

- **Ozone** (J-Link): open `project.jdebug`; it loads `_build/Project.elf`
  and the shared SVD.
- **J-Link Commander** flash example (LED blink verified on Blue Pill):
  ```sh
  JLink.exe -device STM32F103CB -if SWD -speed 4000 \
            -CommanderScript flash.jlink
  ```
  where `flash.jlink` contains `loadfile`, `r`, `g`.
- **MDK / SES**: use the integrated flash + debug buttons.

## Configuration knobs

The main tunables live at the top of `inc/main.h` (generated by `stm32cgen`):

| Macro                 | Default (f103c8) | Meaning                                  |
|-----------------------|------------------|------------------------------------------|
| `HCLK`                | `8`              | System clock in MHz (8–72 for F1, step 4)|
| `SYSTICK_CLOCK_SOURCE`| `0`              | 0 = HCLK/8, 1 = HCLK                     |
| `SYSTICK_ENABLE`      | `YES`            | enable SysTick                           |
| `SYSTICK_IRQ_ENABLE`  | `NO`             | IRQ vs polling mode                      |

To change the blinked pin or add peripherals, edit `PORT_C_CONFIG` in
`inc/gpio.h` (or extend it with `PORT_A_CONFIG` / `PORT_B_CONFIG` using the
same `PIN_CFG` macros) and the matching `IOPx_EN` enable bits. For the
F0/F4/G0 demos, `gpio.h` is regenerated by the script, so adjust the
`stm32cgen` GPIO invocation in the `.sh` script instead.

## F303VC Discovery demo

### Board

STM32F303VC Discovery (Device ID 0x422, 256 KB Flash, 40 KB SRAM1 + 8 KB SRAM2).
8 user LEDs on **PE8–PE15** (active-high). The ST-LINK/V2 on-board provides an
8 MHz HSE clock on the MCO pin (PA8) which is routed to the MCU HSE input.

### Clock

`main.h` sets `HCLK = 72` MHz. `wait_for_clock_stable()` in `rcc.h` configures:

- HSE = 8 MHz (from ST-LINK MCO)
- PLL input = HSE / PREDIV1 = 8 MHz
- PLL multiplier = ×9 → PLL output = 72 MHz
- AHB prescaler = ÷1 → HCLK = 72 MHz
- APB1 prescaler = ÷2 → PCLK1 = 36 MHz
- APB2 prescaler = ÷1 → PCLK2 = 72 MHz

Flash latency is set to 2 wait states with prefetch enabled for 72 MHz.

### GPIO — PE8–PE15 LEDs

All 8 LED pins are configured as push-pull outputs:

```c
#define GPIOE_MODE (                              \
  !0 * PIN_MODE(8,  PIN_MODE_OUTPUT) /* PE8  -- LD4  Blue    */ | \
  !0 * PIN_MODE(9,  PIN_MODE_OUTPUT) /* PE9  -- LD3  Red     */ | \
  ...                                                                  \
  !0 * PIN_MODE(15, PIN_MODE_OUTPUT) /* PE15 -- LD6  Green   */   \
)
```

`init_gpio()` writes `GPIOE_MODER` (and other registers) directly. The
`GPIOE_EN` flag is auto-derived: `init_rcc()` sets `RCC->AHBENR` bit 21 to
clock GPIOE.

### LED chase

SysTick runs at 1 kHz (HCLK/8 = 9 MHz, LOAD = 8999). In polling mode,
`idle()` checks `SysTick->CTRL.COUNTFLAG` each iteration and increments a
64-bit `system_uptime` counter:

```c
uint64_t t = ++*uptime();
uint32_t led_bit = (t >> 9) & 7;         /* LED index 0–7, cycles every 512 ms */
uint32_t led_mask = 1UL << (8 + led_bit); /* PE8–PE15                         */

if (t & (1 << 8)) {                       /* on/off phase every 256 ms        */
  GPIOE->BRR  = 0xFF00;                   /* turn off all PE8–PE15            */
  GPIOE->BSRR = led_mask;                 /* turn on current LED              */
} else {
  GPIOE->BRR = led_mask;                  /* turn off current LED             */
}
```

Bit [8] toggles on/off (256 ms period), bits [11:9] select the active LED.
Result: one LED lights at a time, cycling PE8 → PE9 → … → PE15 → PE8.

### Linker script

GCC linker script places `_estack = 0x2000A000` (top of SRAM1, 40 KB) — matching
the official ST linker scripts which do not place stack in SRAM2. An assertion
guards against overflow:

```ld
ASSERT(_estack - _end >= _Min_Stack_Size,
  "RAM overflow: .data + .bss + stack exceeds 40 KB")
```

The Keil auto-generated scatter file behaves differently: it places stack + BSS
in CCM (0x10000000, 8 KB). Keil defaults to placing ZI/stack in the last IRAM
region, and CCM (`IRAM2`) is configured as the last region in the project
settings. Both builds work correctly. This is specific to the F303 — it is the
only example with CCM mapped at a separate address (0x10000000).

### Building and flashing

```sh
bash ./f303vc_demo.sh        # generate + build (debug target)
# or from the generated directory:
cd f303vc_demo
make debug                   # debug build (-Og -g3 -gdwarf)
make program                 # flash via ST-Link CLI
```

ST-Link CLI requires the `-c SWD ... UR` (under-reset) option to connect
while the MCU is running:

```sh
ST-LINK_CLI.exe -c SWD SWCLK=4000 UR -P _build/Project.hex -Rst -Run
```

## F407VG Discovery demo

### Board

STM32F4 Discovery (MB997C, STM32F407VGT6). 4 user LEDs on **PD12–PD15**
(active-low: pin LOW = LED ON). 8 MHz HSE crystal. On-board ST-LINK does
**not** route MCO to the target.

### Clock

`main.h` sets `HCLK = 168` MHz. `wait_for_clock_stable()` in `rcc.h`
configures:

- HSE = 8 MHz (crystal)
- PLLM = 8, PLLN = 336, PLLP = 2 → 168 MHz
- PLLQ = 7 → USB clock = 48 MHz
- AHB prescaler = ÷1 → HCLK = 168 MHz
- APB1 prescaler = ÷4 → PCLK1 = 42 MHz
- APB2 prescaler = ÷2 → PCLK2 = 84 MHz

PWR voltage scaling set to VOS1. Flash latency = 5 wait states with
prefetch + I-cache + D-cache.

### GPIO — PD12–PD15 LEDs

```c
#define GPIOD_MODE (                              \
  !0 * PIN_MODE(12, PIN_MODE_OUTPUT) /* PD12 -- LD3  Green   */ | \
  !0 * PIN_MODE(13, PIN_MODE_OUTPUT) /* PD13 -- LD4  Orange  */ | \
  !0 * PIN_MODE(14, PIN_MODE_OUTPUT) /* PD14 -- LD5  Red     */ | \
  !0 * PIN_MODE(15, PIN_MODE_OUTPUT) /* PD15 -- LD6  Blue    */   \
)
```

### LED chase

LEDs are **active LOW** (pin LOW = ON). The chase logic uses `BSRR` only
(F4 has no BRR register — all resets are done via BSRR[31:16]):

```c
uint64_t t = ++*uptime();
uint32_t led_bit = (t >> 9) & 3;            /* LED index 0–3          */
uint32_t led_mask = 1UL << (12 + led_bit);  /* PD12–PD15              */

GPIOD->BSRR = 0xF0000000;                   /* all LOW = all on       */
if (t & (1 << 8)) {
  GPIOD->BSRR = led_mask;                   /* current HIGH = off     */
}
```

### Linker script

GCC linker: `_estack` at top of SRAM1 (0x2001C000, 112 KB). CCM (64 KB at
0x10000000) available for `__attribute__((section(".ccmram")))` data.

Keil: IRAM = 112 KB @ 0x20000000, IRAM2 = 64 KB CCM @ 0x10000000.

### Building and flashing

```sh
bash ./f407vg_demo.sh        # generate + build (debug target)
# or from the generated directory:
cd f407vg_demo
make debug                   # debug build (-Og -g3 -gdwarf)
make program                 # flash via ST-Link CLI
```

## L152RB Discovery demo

### Board

STM32L152RB Discovery (MB1075B, STM32L152RBT6). 2 user LEDs on **PB6** (Blue LD4)
and **PB7** (Green LD3), both active-high. No HSE crystal — the board runs from
internal MSI (default after reset) or HSI after clock switch.

### Clock

`main.h` sets `HCLK = 16` MHz. `rcc.h` implements:

1. `configure_flash()` — raises the voltage regulator from Range 3 (1.2V) to
   **Range 2 (1.5V)** before switching clock. This is required because the L1
   voltage regulator defaults to Range 3 after reset, which only supports up to
   ~4.2 MHz (RM0038 §5.1.5, Table 26). At Range 2 (1.5V), 16 MHz requires 1
   flash wait state.

2. `setup_sysclk()` — enables HSI16, writes `RCC_CFGR_SW_HSI`, then polls
   `RCC_CFGR_SWS` until the switch completes.

No PLL is used at 16 MHz; PLL is only enabled when `HCLK = 32`.

### GPIO — PB6/PB7 LEDs

```c
#define GPIOB_MODE (                              \
  !0 * PIN_MODE(6, PIN_MODE_OUTPUT) /* PB6 -- Blue LD4   */ | \
  !0 * PIN_MODE(7, PIN_MODE_OUTPUT) /* PB7 -- Green LD3  */   \
)
```

Both pins are push-pull outputs. `init_rcc()` enables `RCC->AHBENR` bit 1
(GPIOBEN) automatically.

### LED chase

SysTick runs at 1 kHz (HCLK/8 = 2 MHz, LOAD = 1999). The chase pattern
alternates between the two LEDs:

```c
uint64_t t = ++*uptime();
uint32_t led_bit = (t >> 9) & 1;       /* LED index 0–1, changes every 512 ms */
uint32_t led_mask = 1UL << (6 + led_bit); /* PB6–PB7                         */

if (t & (1 << 8)) {
  GPIOB->BSRR = (0x00C0UL << 16);  /* turn off both LEDs                */
  GPIOB->BSRR = led_mask;           /* turn on current LED               */
} else {
  GPIOB->BSRR = ((uint32_t)led_mask << 16); /* turn off current LED    */
}
```

Bit [8] toggles on/off (256 ms period), bit [9] selects which LED. Result:
Blue ON → off → Green ON → off → repeat.

### Flash and RAM

128 KB Flash (0x08000000), 16 KB RAM (0x20000000). Linker script sets
`_estack = 0x20004000`.

### Building and flashing

```sh
bash ./l152rb_demo.sh       # generate + build (debug target)
# or from the generated directory:
cd l152rb_demo
make debug                   # debug build (-Og -g3 -gdwarf)
make program                 # flash via ST-Link CLI
```

ST-Link CLI:

```sh
ST-LINK_CLI.exe -c UR -V -P _build/Project.hex -Rst -Run
```

### Known issue — ST-LINK `-Halt` is unreliable

The ST-LINK CLI `-Halt` option always catches the MCU in reset state on this
board. Use `-Rst -Run` for reliable flash-and-run.

## F446RE demo

### Board

WeAct/Clone STM32F446RE 64-pin board (STM32F446RET6, 512 KB Flash, 128 KB
RAM). One user LED on **PB2** (active HIGH: pin HIGH = LED on) and one user
button **B1 on PC13**. Note that on this board the button is **active HIGH** —
pressing it connects PC13 to 3.3 V — so the pin is configured with an internal
**pull-down** and the firmware samples for a HIGH level. This is the opposite
of NUCLEO boards, where B1 is active-low on a pull-up. The board has no
on-board ST-LINK (its OB clone is unreliable), so J-Link is used for flashing
and debugging.

### Clock — 180 MHz

`main.h` sets `HCLK = 180`. `wait_for_clock_stable()` in `rcc.h` configures:

- HSE = 8 MHz (crystal)
- PLLM = 8, PLLN = 360, PLLP = 2 → 180 MHz
- PLLQ = 6 (unused — no USB)
- AHB prescaler = ÷1 → HCLK = 180 MHz
- APB1 prescaler = ÷4 → PCLK1 = 45 MHz
- APB2 prescaler = ÷2 → PCLK2 = 90 MHz

`configure_flash()` enables the PWR clock, selects regulator **Scale 1**
(`PWR_CR_VOS_1`), waits for `VOSRDY`, then programs the flash with **6 wait
states** plus prefetch and I/D-cache.

The 180 MHz PLL output was verified on this board (TIM2 counting the 8 MHz
HSE over 5 s), so `SystemCoreClock` is hard-coded to `180000000u` — no
auto-calibration is needed. Register values read back via J-Link:

- `RCC_PLLCFGR = 0x06405A08` (M=8, N=360, P=/2, SRC=HSE)
- `RCC_CFGR    = 0x0000940A` (SW=PLL, PPRE1=/4, PPRE2=/2)
- `FLASH->ACR  = 0x00000706` (6 WS + prefetch + I/D-cache)
- `SystemCoreClock = 0x0ABA9500` (180 MHz), SysTick ticking at exactly 1000/s

Beware the classic pitfall: with `RCC_PLLCFGR_PLLP_1` also set (PLLP = /6),
the same `HSE/PLLM × PLLN / PLLP` chain gives exactly **60 MHz** instead of
180 MHz.

### GPIO — PB2 LED, PC13 button, PA2 USART2_TX

```c
#define GPIOA_MODE (                                             \
  SWD_EN     * PIN_MODE(13, PIN_MODE_AF)    /* PA13 -- SWDIO */ | \
  SWD_EN     * PIN_MODE(14, PIN_MODE_AF)    /* PA14 -- SWCLK */ | \
  USART2_TX_EN  * PIN_MODE(2,  PIN_MODE_AF) /* PA2  -- USART2 TX */ )
#define GPIOB_MODE ( PIN_MODE(2, PIN_MODE_OUTPUT) /* PB2 -- LED */ )
#define GPIOC_MODE ( PIN_MODE(13, PIN_MODE_INPUT) /* PC13 -- B1  Button */ )
#define GPIOC_PUPDR ( PIN_PUPD(13, PIN_PUPD_DOWN) /* active HIGH button */ )
```

`SWD_EN` is hard-coded to 1: `init_gpio()` must not switch PA13/PA14 to
analog, or the debug port dies with the firmware running. `init_rcc()`
auto-enables the GPIOA/B/C clock gates from the `GPIOx_EN` flags; PA2's AF7
is written by `uart_init()`.

### SysTick and LED effects

SysTick runs at 1 kHz (`HCLK / 8` = 22.5 MHz, `LOAD = 22499`). In polling
mode `idle()` picks up the 1 ms `COUNTFLAG` and updates the 64-bit uptime:

```c
uint64_t t = ++*uptime();
switch (led_mode) {
  case LED_EFFECT_BLINK:  /* bit [9]: toggle every 512 ms          */
    GPIOB->BSRR = (t & (1ULL << 9)) ? GPIO_BSRR_BS2 : GPIO_BSRR_BR2; break;
  case LED_EFFECT_FAST:   /* bit [6]: toggle every 64 ms           */
    GPIOB->BSRR = (t & (1ULL << 6)) ? GPIO_BSRR_BS2 : GPIO_BSRR_BR2; break;
  case LED_EFFECT_SOS:    /* S O S : dot=100 ms, dash=300 ms       */
    GPIOB->BSRR = sos[(t / 100) % 26] ? GPIO_BSRR_BS2 : GPIO_BSRR_BR2; break;
  case LED_EFFECT_STEADY:
  default:
    GPIOB->BSRR = GPIO_BSRR_BS2; break;
}
```

While **B1 is held down** the LED lights solid as visual feedback.

### Button debounce

PC13 is sampled once per SysTick into a 10-bit shift register (10 ms
debounce); ten consecutive equal samples mean a stable level:

```c
uint32_t tick = (uint32_t)*uptime();
if (tick != last_sample) {
  last_sample = tick;
  history = (history << 1) | (0u != (GPIOC->IDR & GPIO_IDR_ID13));
}
if ((history & 0x3FFu) == 0x3FFu) { /* debounced press  -> advance led_mode */ }
else if ((history & 0x3FFu) == 0u)  { /* debounced release */ }
```

Each debounced press advances `led_mode` (`0=blink 1=fast 2=SOS 3=steady`)
and prints a message over the UART console.

### UART console

`inc/uart.h` is a small hand-written, header-only USART2 driver: **PA2 = TX
(AF7), 115200 8N1**, TX-only. `UART2_PCLK = SystemCoreClock / 4u` (PCLK1 =
45 MHz), and the BRR is computed with rounding:

```c
RCC->APB1ENR |= RCC_APB1ENR_USART2EN;        /* USART2 on APB1       */
uint32_t clk = UART2_PCLK, div = 16UL * UART2_BAUD;
USART2->BRR = ((clk / div) << 4) | (((clk % div) * 16UL) / div);
USART2->CR1 = USART_CR1_UE | USART_CR1_TE;
```

On startup the banner prints the HCLK, SysTick period and baud rate; then a
`t = ... s, mode = ...` line is emitted once per second.

## G431CB demo

### Board

WeAct Studio STM32G431CBU6 (STM32G431CBT6, 128 KB Flash, 32 KB SRAM). One
user LED on **PC6** (green, active HIGH: pin HIGH = LED on). The board has no
on-board ST-LINK (its OB clone is unreliable), so J-Link is used for flashing
and debugging.

### Clock — 170 MHz

`main.h` sets `HCLK = 170`. `init_rcc()` in `rcc.h` configures the **single
PLLR-based PLL** (G4, like F4, has one PLL):

- HSE = 8 MHz (crystal)
- PLL input = HSE / PLLM(2) = 4 MHz    (must be 4–16 MHz)
- VCO = 4 MHz × PLLN(85) = 340 MHz     (must be 128–344 MHz)
- PLLR = /2 → 170 MHz                  (max 170 MHz)
- AHB prescaler = ÷1 → HCLK = 170 MHz
- APB1 prescaler = ÷2 → PCLK1 = 85 MHz
- APB2 prescaler = ÷2 → PCLK2 = 85 MHz

`configure_flash()` enables the PWR clock, selects regulator **Scale 1** and
clears `PWR_CR5_R1MODE` to enter boost mode (required to run the core above
150 MHz), then programs the flash with **4 wait states** plus prefetch and
I/D-cache. `SystemCoreClock` is hard-coded to `170000000u`.

The 170 MHz PLL output was verified on this board by reading the 64-bit `g_ticks`
uptime counter over J-Link: it increments at exactly **1000/s**, which only
holds if the core runs at 170 MHz and SysTick is 1 ms. Register values read
back via J-Link:

- `RCC_PLLCFGR = 0x01005513` (SRC=HSE, M=2, N=85, R=/2, REN)
- `RCC_CFGR    = 0x0000240F` (SW=PLL, HPRE=/1, PPRE1=/2, PPRE2=/2)
- `FLASH->ACR  = 0x00040704` (4 WS + prefetch + I/D-cache)
- `SystemCoreClock = 170000000u` (170 MHz), SysTick ticking at exactly 1000/s

> **Pitfall — G4 PLLR encoding.** Unlike F4 (where `PLLP` is `÷2` for field
> value 0, `÷4` for 1, …), the G4 `PLLR` field is encoded as **0=÷2, 1=÷4,
> 2=÷6, 3=÷8**. Writing `(2-1)` (i.e. `1`) selects **÷4** and yields exactly
> **85 MHz** — half the intended speed. The firmware was first measured at
> 85 MHz for this reason; setting `PLLR = 0` restores 170 MHz. The same
> "off-by-one" trap applies to `PLLQ`/`PLLP` on G4.

### GPIO — PC6 LED

```c
#define GPIOC_MODE ( PIN_MODE(6, PIN_MODE_OUTPUT) /* PC6 -- on-board LED */ )
```

The LED is toggled with `GPIO_BSRR_BS6` / `GPIO_BSRR_BR6` (G4 keeps the legacy
`BRR`-less BSRR model). `init_rcc()` auto-enables `RCC->AHB2ENR.GPIOCEN`.

### SysTick and LED blink

SysTick runs at 1 kHz with `SYSTICK_IRQ_ENABLE = YES` (the `stm32cgen -M`
output wires `TICKINT`). `SysTick_Handler()` increments a 64-bit `g_ticks`
counter; `uptime()` returns it. `process()` toggles PC6 every 250 ms:

```c
if ((now - last_toggle) >= 250u) {
  last_toggle = now;
  GPIOC->BSRR = led_on ? GPIO_BSRR_BR6 : GPIO_BSRR_BS6;
  led_on = !led_on;
}
```

Result: a visible **~2 Hz** blink (on 250 ms / off 250 ms).
